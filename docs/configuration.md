# 配置参考

MolWorld 的配置分为两层：环境变量决定数据库位置和初始管理员身份；后台「参数」保存到数据库，控制展示、上传、标签和交互。环境变量在进程启动时读取，后台参数在每次业务请求中读取。

## 数据库与管理员身份

在仓库根目录创建 `.env`：

```dotenv
DATABASE_URL="file:./data/molworld.db"
REVIEW_USER="admin"
REVIEW_PASS="替换为自己的管理员密码"
```

| 环境变量 | 用途与默认行为 |
| --- | --- |
| `DATABASE_URL` | SQLite 文件地址。相对路径以仓库根目录解析；例如 `file:./data/molworld.db`。绝对路径可写为 `file:/srv/molworld-data/molworld.db`。未设置时使用 `file:./prisma/dev.db`，保留旧实例的默认位置 |
| `REVIEW_USER` | 数据库尚未保存管理员凭据时使用的用户名；无运行时默认值 |
| `REVIEW_PASS` | 与上述用户名配套的初始密码；无运行时默认值 |
| `NODE_ENV` | Next 在开发、构建和生产启动时设置对应模式；生产维护命令显式使用 `production` |

数据库地址只决定 SQLite 的位置。媒体始终位于仓库根目录下的 `data/uploads/`、`data/memes/` 和 `data/trash/`。应用和脚本都从仓库根目录执行；同机多个进程使用同一工作目录和数据库地址。

首次登录使用环境凭据。在后台修改密码后，新的密码散列保存到数据库，后续登录以数据库凭据为准；用户名保持原值。此后修改 `REVIEW_USER` 或 `REVIEW_PASS` 不改变已保存的账号。修改密码同时撤销原有管理员会话，并为当前浏览器签发新会话。

环境文件采用 Next 的优先级，从高到低为：

1. 启动进程时已有的环境变量。
2. `.env.$NODE_ENV.local`。
3. `.env.local`，测试模式跳过这一项。
4. `.env.$NODE_ENV`。
5. `.env`。

维护脚本默认加载开发模式配置；使用生产配置时这样执行：

```bash
NODE_ENV=production pnpm db:migrate
NODE_ENV=production pnpm media:thumbnails
```

修改环境配置后重启所有应用进程。脚本在每次启动时重新加载配置。环境文件保存凭据，留在部署主机上，由部署账号读取。

## 保存后台参数

登录后台，进入「参数」，修改数值后保存。一次保存中的所有参数在同一事务内写入 `AppConfig`；未知键或无效值使整次保存返回错误。数值先四舍五入到整数，再检查范围。数据库中未保存的参数使用下表默认值；未知或无效的历史覆盖值也使用默认值。

下面的范围约束后台配置本身。分页请求仍可请求少于配置下限的条数：例如 `listLimit=24` 时，`/api/memes?limit=1` 返回一条，`limit=100` 最多返回 24 条。

### 调整首页和列表

| 参数 | 默认值 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| `hotLimit` | 24 | 1–60 | 首页热门区域和热门 API 每次展示的最大图片数 |
| `listLimit` | 24 | 6–60 | 全部列表、搜索和公开列表 API 的默认及最大分页条数 |
| `dailyPoolGroups` | 20 | 1–60 | 每个 UTC 日期建立的随机分组数 |
| `dailyPoolSize` | 24 | 1–60 | 每个随机分组的图片数，上限为已发布图片总数 |
| `managePageLimit` | 12 | 4–30 | 管理列表的默认及最大分页条数 |
| `reviewPageLimit` | 12 | 4–30 | 审核列表的默认及最大分页条数 |
| `logPageLimit` | 20 | 5–50 | 操作日志的默认及最大分页条数 |
| `tagPageLimit` | 20 | 5–50 | 标签列表的默认及最大分页条数 |

首页随机展示先选一个当日分组，再按 `hotLimit` 取图；分组不足时从其他已发布图片中补足。分组间可以有重复图片。打开随机页时，服务端检查分组数量和各组有效图片数，按当前参数建立或重建分组。需要主动重新抽样时，在仓库根目录执行：

```bash
NODE_ENV=production pnpm data:daily-pool
```

分页和展示参数在下一次请求中生效；已打开的页面刷新后使用新值。

### 调整公开接口缓存

| 参数 | 默认值 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| `cacheListSeconds` | 30 秒 | 0–3600 秒 | `/api/memes` 的共享缓存时间 |
| `cacheSearchSeconds` | 30 秒 | 0–3600 秒 | 非空查询 `/api/search` 的共享缓存时间 |
| `cacheHotSeconds` | 30 秒 | 0–3600 秒 | `/api/memes/hot` 的 `latest` 和 `hot` 模式共享缓存时间 |

大于 0 时，响应使用 `Cache-Control: public, max-age=0, s-maxage=秒数`。浏览器重新验证响应，支持共享缓存的代理可在该时间内复用结果；设为 0 时返回 `no-store`。这三项控制 API 响应头，首页仍逐次渲染，热门 API 的 `random` 模式始终不缓存。

修改后生成的响应使用新时间，代理已经保存的响应按原有到期时间失效。因此发布、隐藏或修改图片后，列表元数据可能在原 TTL 内保留旧内容；媒体读取仍逐次检查发布状态。

### 调整上传和审核队列

| 参数 | 默认值 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| `uploadMaxSizeMb` | 10 MiB | 1–50 MiB | 单张原图的字节上限，1 MiB = 1,048,576 字节 |
| `uploadCooldownSeconds` | 60 秒 | 0–600 秒 | 同一 IP 两次成功上传之间的间隔 |
| `uploadGlobalCooldownSeconds` | 5 秒 | 0–600 秒 | 全站匿名成功上传之间的间隔 |
| `reviewQueueLimit` | 150 张 | 0–1000 张 | 上传队列容量；设为 0 时暂停接收新上传 |

文件格式为 PNG、JPEG、GIF 或 WebP，服务端核对 MIME、实际解码格式及图像数据；解码像素上限固定为 40,000,000。上传的非空标题在全库中做精确重复检查。队列容量按 `data/uploads/` 对应的待审或旧版隐藏记录计算，正式图库中的隐藏图片不占用容量。

上传记录提交成功后才消耗两项冷却额度；任一额度未恢复都会拒绝下一次匿名上传。相应冷却设为 0 即关闭该项。管理员上传跳过这两项冷却，文件检查、重复标题检查和队列容量仍生效。反向代理接收的请求体还包含 multipart 封装；按最大 50 MiB 文件部署时，代理请求体上限配置为 51 MiB。

### 调整标签规则

| 参数 | 默认值 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| `maxTags` | 8 个 | 1–12 个 | 上传、编辑及补标签时单张图片保存的标签数量 |
| `maxCnTagLength` | 10 字符 | 2–20 字符 | 含基本汉字的标签长度 |
| `maxEnTagLength` | 20 字符 | 2–30 字符 | 其他标签长度 |

文本输入以空白、英文或中文逗号、顿号、分号分隔。每个标签转成小写，只保留英文字母、数字、下划线和基本汉字；随后截断长度、去重，并按输入顺序保留数量上限内的标签。例如 `Mol!，可爱; mol` 保存为 `mol` 和 `可爱`。

修改规则影响后续上传、编辑、重命名和补标签操作，已有标签及关联保持原值。搜索按查询词匹配标题和标签，保留标点和 emoji，不使用标签清洗规则。

### 调整复制、下载和随机切换

| 参数 | 默认值 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| `copyCooldownSeconds` | 3 秒 | 0–60 秒 | 页面复制按钮间隔，以及同一访客申请复制凭据的间隔 |
| `downloadCooldownSeconds` | 10 秒 | 0–60 秒 | 页面下载按钮间隔，以及同一访客申请下载凭据的间隔 |
| `randomCooldownSeconds` | 5 秒 | 0–60 秒 | 浏览器内随机切换按钮的间隔 |

复制与下载分别计时，每种操作的访客额度跨图片共享。服务端在签发一次性凭据时消耗额度；实际复制确认或下载完成时才增加统计。即使随后取消操作，已签发凭据占用的冷却时间仍保留。页面按钮则从点击时开始计时。

复制、下载还各有每 IP 每窗口 10 次凭据申请的额度，窗口长度等于相应冷却秒数，最短 1 秒。将复制或下载冷却设为 0，会关闭访客间隔，IP 额度仍是每秒 10 次。随机切换的冷却由浏览器执行，保存在该浏览器的本地存储中。

### 调整管理员会话与登录

| 参数 | 默认值 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| `loginCooldownHours` | 24 小时 | 1–168 小时 | 同一 IP 的登录尝试窗口长度，每个窗口最多 3 次有效格式的登录尝试 |
| `adminSessionDays` | 7 天 | 1–30 天 | 新签发管理员会话的有效期 |

登录窗口从第一次尝试开始；登录成功清除该 IP 的窗口。第三次密码错误返回 429，`Retry-After` 表示当前窗口剩余秒数。改变 `adminSessionDays` 只影响之后登录或改密时签发的会话，现有会话使用原有到期时间。

## 参数何时生效

服务端每次读取后台配置都查询数据库，同机各进程在下一次读取时取得新值。正在处理的请求继续使用开始时读到的配置；页面中的按钮间隔和分页选项在页面重新渲染后更新。

上传、登录、复制、下载及匿名 API 的限流窗口保存在 SQLite，进程重启后继续有效。修改冷却时间不重算已经建立的窗口到期时间；下一窗口按新值建立。将可关闭的冷却设为 0 时，该项立即跳过检查。

匿名 API 另有固定的每 IP 每分钟 120 次额度；管理员会话有效时跳过这一总额度。客户端 IP 取 `X-Forwarded-For` 的第一项，其次是 `X-Real-IP`，两者均缺失时共用 `unknown` 分组。生产代理用实际来源地址覆盖这两个请求头，并使应用端口只接受代理连接。具体设置见[HTTPS 代理配置](deployment.md#配置-https)。
